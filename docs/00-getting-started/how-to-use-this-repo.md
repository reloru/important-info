# How to Use This Repository

This knowledge base is written to work two ways: as a **course** you read in
order, and as a **reference** you dip into. Pick the path that fits.

## Reading paths by role

### Site owner / non‑technical stakeholder
You don't need to write code, but you're accountable for the result — including
legally. Read:
1. [The website life cycle](website-lifecycle.md)
2. [Roles & responsibilities](roles-and-responsibilities.md)
3. [Planning & Strategy](../01-planning-and-strategy/README.md) (skim)
4. [Legal & Compliance](../10-legal-and-compliance/README.md) (in full)
5. [Maintenance & Operations](../09-maintenance/README.md) (so you budget for it)

### Freelancer / agency
You carry both the craft and the client relationship. Read everything, but pay
special attention to:
- [Budgeting & scoping](../01-planning-and-strategy/budgeting-and-scoping.md)
- [Maintenance plans](../09-maintenance/maintenance-plan.md) (recurring revenue *and* risk)
- [Legal & Compliance](../10-legal-and-compliance/README.md) (who is liable — you or the client?)
- [Templates & Checklists](../templates/README.md)

### Developer joining a project
Get productive fast, then go deep:
1. [Development Best Practices](../03-development-best-practices/README.md)
2. [Accessibility](../04-accessibility/README.md),
   [Performance](../05-performance/README.md),
   [Security](../07-security/README.md)
3. [Deployment & DevOps](../08-deployment-and-devops/README.md)

### Learner / student
Read the sections in numeric order, 00 → 10. Each builds on the last and
follows the natural order of a real project.

## How each section is organized

- Every section folder starts with a `README.md` that summarizes the topic and
  links to its pages.
- Pages open with *why this matters*, then move to *what to do*, then a
  *checklist* or *decision table* you can act on.
- Cross‑cutting concerns (accessibility, security, performance, legal) get their
  own sections **and** are flagged inline with callouts wherever they touch a
  topic.

## Callout legend

| Callout | Meaning |
|---------|---------|
| ✅ **Do** | A recommended practice |
| ❌ **Don't** | A common mistake to avoid |
| ⚖️ **Legal note** | Where the topic intersects with the law |
| 🔒 **Security note** | A security implication |
| ♿ **Accessibility note** | An accessibility implication |
| ⚡ **Performance note** | A performance implication |
| 💡 **Tip** | A useful shortcut or nuance |

## Keeping it current

Web standards, tooling, and especially **laws** change. Treat dated material
with appropriate skepticism, follow the primary‑source links, and see
[CONTRIBUTING.md](../../CONTRIBUTING.md) if you want to propose an update.
