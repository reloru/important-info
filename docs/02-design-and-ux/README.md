# 02 · Design & UX

Design is not decoration. It's the set of decisions that determine whether
people can actually *use* your site to accomplish their goals — and whether they
trust it enough to try. This section covers usability, responsive design, design
systems, and content strategy.

## The distinction that matters

- **UX (User Experience)** — how it *works*: flows, structure, clarity,
  findability, error handling. Can a user reach their goal?
- **UI (User Interface)** — how it *looks and feels*: layout, color, type,
  spacing, components.

Good UI on bad UX is lipstick on a maze. Get the experience right first, then
make it beautiful.

## Cross‑cutting reminders

> ♿ **Accessibility note:** Accessibility is a *design* responsibility, not just
> a development one. Color contrast, focus order, target sizes, and clear labels
> are decided in design. Retrofitting them later is far harder. See
> [Accessibility](../04-accessibility/README.md).

> ⚡ **Performance note:** Design decisions have performance costs — heavy
> imagery, huge hero videos, many web fonts, and layout that shifts as it loads
> all hurt real users. Design *with* a performance budget. See
> [Performance](../05-performance/README.md).
